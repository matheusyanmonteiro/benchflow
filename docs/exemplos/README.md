# Exemplos para a apresentação

Os arquivos abaixo são exemplos preenchidos, não templates ativos. Eles mostram o nível de informação esperado em uma colaboração profissional.

## Issues

1. [`issues/01-bug.md`](issues/01-bug.md): defeito reproduzível, impacto, severidade e evidências.
2. [`issues/02-feature.md`](issues/02-feature.md): necessidade do usuário, proposta e critérios de aceite.
3. [`issues/03-pedido.md`](issues/03-pedido.md): solicitação operacional delimitada, prazo e definição de pronto.

## Pull requests

1. [`pull-requests/01-bugfix.md`](pull-requests/01-bugfix.md): correção ligada à issue de bug.
2. [`pull-requests/02-feature.md`](pull-requests/02-feature.md): entrega incremental de uma feature.
3. [`pull-requests/03-pedido.md`](pull-requests/03-pedido.md): manutenção de CI solicitada pela equipe.

Na demonstração, crie issues reais copiando esses cenários e use `Closes #<número>` nos PRs para mostrar a rastreabilidade automática.
